# 单虚拟屏架构方案（大屏取景器设计）

- 日期：2026-09-20
- 状态：已评审可行，待实施
- 背景讨论：见 PROJECT_STATE.md "下拉实验全线回退" 与 "纯镜像架构" 各节

## 1. 栨心思想

**一块我们拥有的大虚拟屏（VD），内外双物理屏只是它的两个"取景器"：**

- **内屏**（展开时可见）：显示 VD 的**全部**内容，1:1。
- **外屏**（封面，永远可见）：**永远只裁剪显示 VD 的右半区**，1:1。
- **开合 = VD 尺寸调整**，不是内容换屏：
  - 折叠态：VD 缩为右半尺寸（≈1182×1672 竖屏），外屏显示 VD 的 100%。
  - 展开态：VD 扩为全宽（2364×1672 横屏），内屏显示全部，外屏显示右半（U∈[0.5,1] 裁剪）。

内容从头到尾在**同一块 VD** 上，不存在接力、不存在换绑、不存在主屏切换——"开合不黑屏"从机制上被消灭，而不是被遮住。

## 2. 为什么这是对今天所有实验的收敛

| 今天踩的坑 | 单 VD 架构下 |
|---|---|
| 5↔6 换主屏在 composer 层硬清一帧，遮罩盖不住自己 | **永不换主屏**：固定 hold 一个 state（建议 6）不翻转；两块物理面板只是渲染我们输出窗的画布，谁是 display 0 无关紧要 |
| 撤出/冻结帧/换向编排复杂且仍闪 | 不存在换向；开合只是 resize + 裁剪系数两个连续参数 |
| 封面信箱/比例失配 | 封面 1:1 裁剪右半（裁剪管线 2026-09-20 已真机验证）；内屏展开 1:1 全显 |
| 两套 DuoHome 实例、双内容管线、跨屏同步 | 一套；DuoHome 只做响应式布局 |
| 触摸两套映射 | 裁剪感知坐标映射（已写好验证过：外屏 x 映射到 VD 右半） |

## 3. 几何尺寸（lhasa 实测）

- 内屏：1672×2364（物理竖屏），展开使用时横屏 2364×1672，折痕竖直居中。
- 内屏右半：**1182×1672**（横屏取向下的右条，竖形）。
- 封面屏：**1168×1712**（竖屏）。
- 右半 vs 封面：**近似一致（差 3~4%）**，非完全一致。
  - 处理建议：VD 按内屏半区取整尺寸建（如 1184×1672），封面微量拉伸（3%，无感）；
  - 备选：VD 按封面尺寸建，展开时内屏左右各余几像素黑边。
- DPI：两屏名义都是 440（实际 PPI 385.3/381.9，差 0.9%，可沿用现有补偿 density 逻辑取其一）。

## 4. 组件映射（现状 → 目标）

| 组件 | 现状（DuoHome 双 VD） | 目标（单 VD） |
|---|---|---|
| helper `createDualContent` | 建两个 OWN_CONTENT VD | 建一个 VD；SECONDARY_HOME 只启一个 DuoHome |
| `VirtualDisplay.resize` | 仅手势带收放 | **开合尺寸切换**（折叠↔展开两档，角度阈值+滞回） |
| FixedDualOutput ×2 | 各自 VD→GPU→面板 | 内屏=全显（buffer=canvas 1:1）；封面=裁剪管线（buffer=VD 全尺寸，shader 采样 U∈[0.5,1]，折叠时 U∈[0,1]） |
| state hold | 常驻 5 或 6 | 常驻 **6**（或 5）永不翻转；主屏归属不再参与任何逻辑 |
| 帘幕 curtain | 折叠遮非可见面板 | 保留：折叠时内屏黑幕，展开恢复 |
| 触摸注入 | dualTouch(contentId) | 同通道不变；外屏坐标经裁剪逆映射（含折叠/展开两档） |
| 折痕动画 shader | 现有 tilt/crop/blur | 复用为开合过渡的视觉遮盖（见 §6） |
| HomeControlPanel / HomeStatusBar | 已恢复活跃 | **必需品**：VD 上无 SystemUI 下拉，控制中心/通知全自制（现状即目标） |

## 5. 关键技术点与已验证结论（2026-09-20 实验存档）

1. **裁剪采样**：SurfaceTexture 变换矩阵右乘 U∈[0.5,1] 裁剪矩阵（列主序 `[0.5,…,0.5,…,1]`）；**输入 buffer 尺寸必须与 VD 严格一致**，否则 DisplayManager 会再叠一层保比例 letterbox（今天黑边 bug 的根因）。
2. **direct 直通与裁剪互斥**：裁剪必须走 GL（direct 换面无变换级）；封面管线 directAllowed 恒 false，GPU 全程跑（120Hz 一面全屏 GL 拷贝可承受）。
3. **TextureView 不能用 INVISIBLE 等首帧**（不分配 surface）——用 alpha=0 + onSurfaceTextureUpdated 淡入。
4. **VD 在途 resize**：`VirtualDisplay.resize()` 现有代码已用于手势带（1168×~1692↔1712），大幅跨取向 resize 未验证——预期触发 activity 重建（与原生折叠屏行为一致）。
5. **冻结帧遮罩**：PixelCopy 从输出 surface 抓当前帧 + 全屏 ImageView 窗——resize/重排瞬间盖住 VD 内部白闪（FreezeMask 经验，注意抓帧要在 resize 前）。
6. **面板旋转补偿**：内屏挂载带旋转（`ProjectionMath.turn(inner,rotation)=(rotation+1)%4`），输出窗纹理变换必须走 turn 补偿；用户视角 hinge 右 = 折叠构建时的物理上半。

## 6. 开合过渡编排（v1 目标）

```
折叠稳态：VD=半区竖屏；封面=100%裁剪；内屏=帘幕黑
  ↓ 角度 > 展开阈值（如 120°，滞回 60/120）
过渡：
  1. FreezeMask 盖内屏（抓 VD 当前帧）
  2. VD resize → 展开全宽横屏；DuoHome/应用重排
  3. 帧稳定后（VD 出帧回调 / ~600ms）撤内屏帘幕 → 内屏全显
  4. 封面裁剪系数动画 U∈[0,1]→[0.5,1]（shader 连续参数）
展开稳态：VD=2364×1672；内屏全显；封面右半
  ↓ 角度 < 折叠阈值（60°）——反向同理
```

要点：封面**全程**显示"VD 右区"，过渡中只有裁剪窗口在动，封面视角永不换内容源。

## 7. 风险与未决

1. **跨取向 resize 的应用重建体验**：activity recreate 的白屏/闪跳需冻结帧盖住；个别应用可能不响应 resize（保持旧布局）——观察清单机制。
2. **DuoHome 响应式布局**：竖屏 4×5 ↔ 横屏宽列（约 8×5?）的网格/搜索/dock 适配是主要 UI 工作量。
3. **输入法**：VD 上 IME 策略已通（setDisplayImePolicy 0），跨取向后复查。
4. **锁屏/灭屏**：维持现有行为（锁屏即停会话，解锁自动恢复）。
5. **Helper 8s 拓扑冷却**：不再触发（无翻转），仅会话冷启动相关。
6. **通知**：VD 上无状态栏，通知入口=自制面板（DuoNotifications 已有）。

## 9. 今天实验结论速查（防重踩）

- 原生下拉/面板只存在于 display 0；我们的 a11y 覆盖窗（层 311000）压在 SystemUI（151000）之上，主屏原生面板必须撤出才可见。
- 5↔6 换主屏：composer 级硬清一帧，应用侧任何遮罩（含双冻结帧）都盖不住。**已定性为死路。**
- 无 OWN_CONTENT_ONLY 的 VD 可实时镜像 display 0（通道已验证后回退移除，需要时按今天记录重建）。
- shell `input swipe` 能唤原生面板；a11y `dispatchGesture` 不能。
- 翻页帧率：呈现节流 ≥8ms + 输出窗 120Hz 投票（另一会话的修复，已合入本工作树）。
